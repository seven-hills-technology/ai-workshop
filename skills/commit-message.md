---
name: commit-message
description: House style for commit messages in this repo. Applies when writing or editing a commit message.
trigger: preparing or revising a git commit message
---

When writing a commit message for this repo:

1. **Subject line** — imperative, lowercase, under 60 characters. No trailing period. Prefix with the area touched when it's clear (`api:`, `web:`, `docs:`, `agents:`, `skills:`).
2. **Blank line** between subject and body.
3. **Body** — what changed and *why*, not how. Two short paragraphs max. Skip the body for one-line changes.
4. **Don't** include the diff, file list, or "generated by X" footers unless explicitly asked.

Examples:

```
api: add status filter to todos endpoint

Spec-driven exercise from workshop section 3. Filters on the
existing Todo.status field; no schema change.
```

```
docs: tighten prompt-writing section
```

When in doubt, shorter is better. The diff has the details; the message gives the reason.
